机器人搭建链路 · 拆解

「千里速闻」这个飞书机器人是怎么搭出来的

你在用的发消息后台,背后是两半拼起来的:飞书那边注册的一个"机器人身份",加上公司自己写的一个后台服务。分开看就清楚了。

核心:这套东西跟公众号没有任何关系。「千里速闻」是一个企业自建应用——消息以这个应用的身份直接发到员工会话里,中间没有公众号那一层。
第一半 · 飞书侧:注册机器人身份
能力地图 第一层
1

在飞书开放平台建应用

公司研发/IT 登录飞书开放平台,创建企业自建应用,取名「千里速闻」,开启"机器人"能力。

申请权限 + 发布上线

申请发消息权限,走公司内部审批发布。发布后,这个应用就在每位员工的飞书里变成一个能收消息的会话联系人。

拿到两把钥匙

飞书发给这个应用 App ID 和 App Secret——相当于机器人的账号密码。身份到此建成,但它自己不会动,得有人拿钥匙去指挥。

App ID / App Secret
第二半 · 公司侧:写后台服务指挥它

4

后台服务:换临时通行证

公司写的程序拿 App ID/Secret 去飞书换一个临时通行证。它两小时过期,程序会自己偷偷刷新,你完全感觉不到。

tenant_access_token

能力地图 第二·三层
5

拼 JSON + 调接口

把你在界面上填的内容拼成飞书要的 JSON 格式,POST 给飞书的发消息接口。你贴的"消息模板正文"就是这里的卡片 JSON。

POST im/v1/messages
↓
你在这里
6

配一个网页界面

给这个后台服务套一个可视化界面——就是你天天用的"新增消息"页。你选应用、填收件人、贴模板、点发送,每一下都是在给后台喂参数。

两半怎么接上:后台服务(第二半)拿着应用(第一半)的钥匙,去调飞书接口——身份是飞书给的,动手的是公司的程序。

一条线看完:从建应用到消息送达

建应用「千里速闻」 → 拿 App ID/Secret → 后台服务换 token → 拼卡片 JSON → 你填表点发送 → 调飞书发消息接口 → 消息直达员工会话
飞书侧(身份) 公司侧(后台服务) 你的操作
对你的意义:你现在站在这条链路最上游的界面上;搭建它的人,主要工作量花在"后台服务"那块——也就是能力地图的第二层。第一层(建应用/批权限)是配置活,第三层(卡片 JSON)你贴"消息模板正文"时其实已经天天在碰了。你那个练手脚本走的是群 webhook,连换 token 都省了,但"拼 JSON → 发出去"的内核跟公司这套是同一回事——吃透它,就等于摸到了这套系统的发动机。
