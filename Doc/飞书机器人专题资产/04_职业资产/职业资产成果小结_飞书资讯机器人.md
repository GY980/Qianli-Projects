# 职业资产成果小结 · 飞书自动资讯推送机器人

> 完成日期:2026-08-10
> 一句话:从"这机器人怎么搭的"这个好奇心出发,独立完成了一套每天自动抓取汽车资讯并定时推送到飞书的系统,从需求到上线全程自己走通。

---

## 一、这个项目是什么(用于简历/面试的一句话版本)

**发现团队每天手动整理资讯推送耗时耗力,我用 Python 自研了一套"自动抓取汽车之家资讯 + 定时推送到飞书"的系统,把这块重复工作完全自动化——每晚自动抓取当天资讯并存档,次日早上9点自动推送。**

这句话可以直接用在简历的项目经历栏,或面试被问"讲一个你主动做成的事"时开口。

---

## 二、我实际做了什么(过程)

1. **搞清了原理**:分辨了飞书两种机器人(群 webhook / 企业自建应用)的区别,看懂了公司现有"千里速闻"推送后台背后的技术链路(自建应用 + 后台服务调 im/v1/messages 接口)。
2. **选了合适的技术路线**:判断出定时推送该用 API/webhook 机器人(可控可靠),而非飞书智能体(为对话设计,不适合);并选了零审批、个人可操作的群 webhook 路线快速落地。
3. **动手实现**:用 Python 写了抓取 + 组装飞书消息卡片 + 推送的完整脚本;解决了数据源选择(改用 /all/ 全部资讯列表页,排除置顶旧文)、标题清洗、去重等实际问题。
4. **部署上线**:用 Windows 任务计划程序配置了两个定时任务(23:59 抓取存档 / 09:00 推送),实现无人值守自动运行。
5. **踩坑与调试**:独立处理了 PowerShell 与 curl 语法差异、中文编码、网页结构解析失效、时间格式不规整等一连串真实问题。

---

## 三、技术链路(能说清楚就是加分)

数据源(汽车之家 /all/ 列表页)→ Python + requests 抓取网页 → BeautifulSoup 解析出文章标题与链接 → 组装成飞书消息卡片 JSON → 通过群机器人 webhook 推送到飞书 → Windows 定时任务实现每日自动运行。

两个脚本经一个 JSON 文件解耦:`autohome_fetch.py`(抓取+存档)与 `autohome_send.py`(读档+推送),互不干扰、便于排查。

- **自驱与结果导向**:没人要求我做,我从好奇心出发主动做成,并真正解决了本职工作里的重复劳动。
- **跨越了业务岗与技术的门槛**:作为标准/合规/资讯背景的人,我能读写 Python、调用 API、解析网页、配置自动化。这让我以后能与研发有效对话、判断技术方案。
- **业务+技术的结合**:这不是孤立炫技,而是用技术手段提升资讯本职工作的效率——这正是各行业都稀缺的复合能力。

**在智驾这类高度技术化的行业,"懂技术的业务人"比"纯业务人"更具竞争力,这个项目是这一标签的有力证据。**

## 五、诚实的边界(避免高估,面试才不露怯)

- 这是一个轻量自动化项目,定位是"业务人的技术加分项",不等同于专业开发岗所需的系统设计、工程规范能力。
- 走的是群 webhook 路线;若要迁移到公司"千里速闻"那种给全员发的自建应用,还需掌握 App ID/Secret 换 token 的鉴权流程(能力地图第二层核心,尚待实操)。
- 定时任务依赖本机开机;要做到 7×24 稳定运行需部署到云端。

把边界讲清楚,反而显得你判断力清醒、不吹牛,这在面试里是加分项。

## 六、怎么把它变成更大的职业资产(下一步)

单个项目分量有限,但**同一套"抓取+整理+推送/存档"的能力可以复制**。建议再做两三个同类小自动化,形成系列:

- 竞品动态监控(定时抓取指定车企/品牌的新闻)
- 政策法规变化提醒(监控相关标准/法规页面更新)
- 行业数据周报(定时汇总某类数据自动成表)

一旦手里有一组这样的成果,职业标签就能从"资讯岗"升级为"懂技术、能用工具解决业务问题的资讯/标准专家",跳槽议价能力显著不同。
