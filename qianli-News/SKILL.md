# 智驾新闻资讯 HTML 页面

把智驾相关的一手消息做成一张大字号的 HTML 推送页面,供内部快速速览。有两种形态,开工前先判断属于哪种:

- **A. 新车要闻**——输入是新车智驾配置(文档/配置表截图)。结构 = 新闻式 Hero(kicker「智驾新车要闻」+「内部速递」+ 品牌小字 + 车型大字渐变)+ 本期重点横幅 + 各车分区(硬件卡 + feature-headline 卖点卡 + 功能网格)。**价格落看板 status 字段 + 车型分区的 `.pbadge` 胶囊,不做大号价格 Hero。**
- **B. 功能升级资讯**——输入是一组升级/新增卡片(如「华为乾崑智驾 ADS 5 首版本升级」的小红书图集、「腾势 N8L/N9 OTA」官方图集、「小米多车型 1.17 OTA」),**没有价格**,按主题分区展示每条升级点,可嵌入原图配图。

## 核心原则(通用)

1. **只体现智驾内容**——只保留驾驶辅助的硬件与功能/升级点。座舱、音响、车控、底盘、电池、被动安全件删除。若用户一开始选了「官方图卡全上」,后续也常会让你**删掉座舱交互整个分区**(K歌/数字形象/DiLink/通话播报等),按指示删,并同步更新看板 highlight 保持一致。
   - ⚠️ **例外要连带改免责口径**:用户偶尔会点名要求补进非智驾内容(如与众08 的「AI 大语言模型座舱」「底盘智能预瞄」)。这时**必须同时把该页 footer 免责里「只列驾驶辅助硬件与功能」那句删掉**,否则页面自相矛盾;改完主动告知用户「已按你的要求补入,同时调整了免责口径,要恢复严格智驾随时说」。
2. **功能配置列表 = 官方配置详情,一字一句照官方来,严禁自行补充或从品宣文字反推功能项**(重要)。
   - **只列官方配置表/截图里逐项列出的功能**。品牌宣传文案里的花哨能力名(「路口通行/红绿灯读秒/博弈变道/全场景避障绕行/无车道线通行/窄路多把掉头/环岛行驶」「AVP 下车泊入」「车头泊入/车尾泊出/偏置泊车」等)常常**只是品宣话术,并不在配置表功能项里**——绝不能当功能项塞进功能网格。曾把这类品宣词拆成 CNOA/HNOA 细分 chip 及泊车细分,被用户揪出"配置截图里根本没有",全部清除。
   - **不确定某项在不在官方配置里,就 Read 配置截图逐张核对;核不到就不放。**
   - **官方有分类就照官方分类,官方没分类就不要自己造分类,直接平铺列表。** 例:海豹06(懂车帝口径)是单个「驾驶功能」大类下平铺,就别自作主张拆成「行车辅助/泊车辅助/主动安全」三组;零跑A05 官方明确分「领航辅助/行车辅助/主动安全/泊车辅助/辅助影像」,就照它的分类分组。**2026-08-24 新款红旗HS5 又踩一次**:我按语义自造了「感知与影像硬件 / 巡航与领航 / 泊车 / 主动安全预警」四组,用户直接说「不需要把功能进行区分,直接像他这样列出来就行」——四个 `grp-title` 全删,改成**照官方配置表从上到下的原始顺序平铺**。**没有官方分类时的默认动作 = 平铺,不是分组。**
   - 也不要凭空加官方没有的汇总项(如自造的「ICC 车道巡航辅助」当独立功能项)。
   - **同一区块内功能卡版式统一**(如统一两个一行),不要一个功能单独占一行、别的两个一行,参差不齐。
   - **配置表里带 `*` 的功能 = 待 OTA 解锁**,别当已交付功能平铺:功能卡右侧加 `.ota-tag`(如「Q4 OTA」),分区顶部 `sys-note` 写一句图例说明解锁时间。
   - **官方配置里全是「-」的项(如某车全系没有的城市记忆领航)不要列出来。**
3. **文字描述(官方品宣)与功能配置列表严格分开**(重要)。品宣描述性整段文字(营销话术、成串的能力罗列)放上方的 **feature-headline 卖点卡**里,**不要混进下方的功能配置列表**。功能列表只放客观配置项(缩写/图标 + 功能名)。即"上面讲故事、下面列配置",两者互不越界。
4. **同一个事实只出现一次(用户红线:「不要重复的信息反复呈现」)**。这条驱动了大量删改,做页面时按"三区分工"直接一次到位:
   - **Hero `.lead` = 新闻事件交代**:何时何地什么事 + 各车搭什么方案 + 上市/预售/盲订状态,一句话说完。**不写免责句**(「本页只梳理驾驶辅助…」属 footer)。
   - **本期重点横幅 = 智驾功能亮点 / 品宣看点**。**不写价格**(价格已在 `.pbadge`),**不写台账式元信息**(哪几款有配置表、哪几款没有、各车什么状态),那样读起来像免责声明。desc 也**不要重复标题已给的方案名**。
   - **footer 免责 = 全部台账 + 口径说明**,且**分区末尾的 `sys-note` 不要和 footer 免责说同一件事**(如「大汉EV 暂未公布逐项配置表」这句,只在 footer 留一处,分区里那句删掉)。
   - 硬件卡下的「以上共 N 颗感知元件」这类求和句、feature 卡里「配置表中三个预售版本上述项均为标配」这类补充句,用户都会要求删——**别写**。
5. **免责/说明控制在 100 字以内**。用户在 2026-08-24 两次说「免责声明以及说明精简一下,目前太长了」(180→98→75 字、215→85→58 字)。写法:一句「信息依据 X、Y 官方资料整理」+ 最多两条真正必要的口径提示 + 「价格与配置以官方为准。」收尾。日期行、署名重复行、示意性长句一律不要。
6. **禁用词/句式清单(用户明确否掉,长期生效)**:
   - 拔高词:**顶级、高阶、同级跨代领先**。
   - 竞技/对标框架:**vs、对标、同台、PK、较量**(多车各搭不同方案不是对标关系,用顿号并列即可)。
   - **齐发**(多车常是不同状态、不同团队,别写"三车齐发/齐发上市")。
   - 对冲/转述词:**官方称、官方口径、官方强调、宣传可实现**——要么就是官方配置里的事实直接陈述,要么不写。
   - 宣传性尾巴:「越用越懂家」「越用越默契」这类修饰尾。
   - 冗长句式:「向…迈进」改成直陈句(「N维安全目标:全时速、全方向…」)。
7. **不要做「快速导览」车型卡片区**(digest-panel 里 banner 下面那排 nav-card / nav-grid,含品牌+车型+价格+ztag)。用户明确说「你记住以后不需要这一部分」。**多车页 = Hero 导语 + 本期重点横幅 + 各车分区,直接进车。** `.digest-panel` 里只留 `.banner`(`.title` + `.desc`)。
8. **不要做「数据条」(stat-row 卡片区)**——即本期重点横幅下方那排 3 个数字卡(如「8项 新增功能 / 6项 无人机相关 / 7次 OTA升级」)。用户明确说「记住以后不需要这一部分」。横幅之后直接进 section-title,不要插数字统计卡。
9. **字号整体偏大**——正文 18px,主标题 60px(新闻标题式变体 44px),section-title 30px,适合推送速览。
10. 每次开工前先问清楚:①本期重点;②形态 A/B(A 还要问车型分组怎么分页);③内容范围(严格智驾 / 官方图卡全上);④是否嵌入配图;⑤是否要浅色/明亮背景(默认深色科技蓝)。**主色不用再问——默认科技蓝 `#2D7FF9`**(华为系页面才换华为红)。**页面默认内置「导出长图」按钮**,不用再问。
11. **交付前逐条核对文案增删**——用户会连着十几轮点名删句/删标签/改颜色/合并卡片。**只改指定的那处,不要顺手改动或删掉别的内容**(曾把"只删标题下一句"误解成删整段差异说明,被纠正)。改完把「删了什么/移到哪」一句话回报,不长篇复述页面内容。
12. **品牌归属要写全**——车型分属集团,品牌标写母集团+子品牌(如 魏牌属长城 → 「长城魏牌 WEY」;与众属大众安徽 → 「大众安徽与众」;大汉EV → 「比亚迪王朝」)。开工前若不确定归属先跟用户确认。
13. **数据对不上就当面问,别硬填**。做 5 车页时积累了一批未解问题(红旗HS5「主动对话系统」是否即"主动刹车"、「车道级导航7」尾部的 7 是不是脚注号、山海L7 PLUS 官方指导价 11.99–16.99万 vs 配置截图 175900 元、红旗HS5「共推出5款车型」vs 截图 7–8 个价格列)。做法:**页面里按最保守口径写或先不写,同时在交付说明里逐条列出待用户确认的疑点**,不要自己圆。
14. **交付后主动核对全文 + 图片顺序**——①提取正文纯文本(剥掉 base64、`<svg…>` 换成 ◆)通读是否有错字/多余句;②每张内嵌图 base64 用 md5 比对源裁图,确认 alt↔源图一一对应;③易混的图再 Read 一眼确认。

## 启境GX7 教训总结(2026-09-08,长期生效)

以下是从启境GX7页面制作过程中(十几轮修改)提炼的具体教训,可直接减少未来页面的修改次数:

14. **单车页价格 badge 放 `.car-header`,不放 Hero**——Hero 只放 kicker+品牌+车型名+导语;价格/日期/车型数胶囊放在横幅之后的 `.car-header` 车型信息卡里。**开工时就照这个结构写,别先放 Hero 再被要求移走。**
15. **`.car-header` 车型信息卡至少含「智驾方案」ch-note**——智驾方案写系统名+架构定位。**如果有其他值得展示的信息(如芯片、算力),优先放芯片/算力行;如果没有,则补「感知硬件」行**(一句话硬件清单:激光雷达×N · 毫米波×N · 摄像头×N…)。即:感知硬件是 car-header 的补充信息位,不是必填项。
16. **传感器展示格式视官方信息粒度而定**——**① 官方提供了各方向传感器位置与数量**(如前向896线×1+4D毫米波×3…)时,用三列纵向卡片(`.safety-grid.tri` + `.safety-item.vcol`),前向/侧向/后向并排一行,每卡标题为方向名,下方传感器逐行竖排。**② 官方只给了传感器名称和总数**时,沿用之前的格式:大数字+标签的硬件卡网格(`.hw-grid`)。
17. **多条 sys-note 合并为一条**——传感器区不要拆出「总述句」「硬件明细句」「同级唯一句」三条 note,合并成一条,用中文分号「；」分隔三段。**同理,任何同一区域内的多条说明性 note 都应合并。**
18. **功能分组用 `grp-title` 合并于同一 `feature-block`**——领航&巡航/泊车/安全辅助三个小标题用 `<h4 class="grp-title blue">` 统一左对齐,放在同一个 `.feature-block` 内。**不要每个分组各起一个 `feature-block`+`sub-title`,那样标题间距过大且结构松散。**
19. **`sub-title` 用 `<h3>` 语义化标签,不用 `<div>`**——SEO 和结构正确性。
20. **用 CSS class 控制间距,不用内联 `style="margin-top:Npx"`**——`.feature-block{margin-top:60px}` / `.hw-block{margin-top:48px}` 统一管理。内联样式难以维护且容易被遗漏。
21. **功能项英文缩写必须照抄官方配置表,不要自行编造**——大部分配置列表都有明确的英文缩写,且各车企命名不同(如华为用「园区领航辅助 NCA」,其他车企可能用不同缩写)。**规则:如果官方配置表给了缩写就用人家的;如果没给缩写,用线性 SVG 图标代替(见关键样式约定),不要自行猜测或套用其他车企的缩写。**
22. **CSS class 添加后必须验证已写入**——多次 Edit 因 old_string 匹配失败导致 CSS 规则(如 `.safety-grid.tri`、`.vcol`)未实际写入文件,页面布局因此错误。**每次添加 CSS class 后,用 grep/Read 确认规则存在。**
23. **并行 Edit 同一文件有风险**——当多条 Edit 的 old_string 有重叠区域时,部分 Edit 可能静默失败。**关键结构改动应顺序执行,或并行后统一验证。**
24. **免责声明不要出现「截图」字眼**——用户要求写「依据官方预售资讯及配置详情整理」,不写「配置表截图」。口径措辞:资讯+配置详情。
25. **拔高修饰词(如"同级最强")的使用视官方品宣而定**——如果车企官方品宣明确使用了"同级最强"等说法,我们可以在卖点卡(品宣区)中引用;但如果官方没说,不要自行添加。**注意:之前将"同级最强"列入禁用词是过度泛化,已纠正。禁用词清单仍保留"顶级""高阶""同级跨代领先"等纯虚构拔高词。**
26. **版本/配置名称必须逐字核对官方截图**(2026-09-07 启源Q06 教训):将"700 智尊型天枢领航Ultra版"误写为"智享型",被用户纠正。**规则:配置截图里的版本全称(如"700 智尊型天枢领航Ultra版")要逐字抄写,尤其"智尊"vs"智享"这类形近字,做完页面后 grep 全文搜索一遍确认无误。看截图时在笔记里记下确切版本名,不要凭印象写。**
27. **sys-note 位置 = 紧跟 section-title 下方,不是区块末尾**(2026-09-07 启源Q06 教训):硬件区说明配置来源的 sys-note 一开始放在了所有硬件卡片之后,用户要求移到标题正下方。**规则:说明"以下为 XX 版配置"的 sys-note 永远紧跟 `.sub-title` 之后,让读者先看到口径再看数据;不要放在区块底部变成"事后说明"。**
28. **sys-note 措辞精简,只说来源版本**(2026-09-07 启源Q06 教训):功能网格 sys-note 原写"以下依官方配置表 长安天枢领航 分区逐项列出,配置截图取自 700 智尊型天枢领航Ultra版。"被改为"以下功能配置取自 700 智尊型天枢领航Ultra版 官方配置表。"**规则:sys-note 一句话说明配置来源版本即可,不要重复系统名(标题已给)、不要说"分区逐项列出"(读者看得见)、不要说"配置截图"(改说"配置表"或"配置详情")。**
29. **footer 免责不出现"截图"字眼**(2026-09-07 启源Q06 教训):用户要求删除"配置截图"中的"截图"。**规则:footer 免责写"官方资料及配置详情整理",不写"截图";sys-note 里也用"官方配置表"代替"配置截图"。**
30. **横幅可用 `.hl-sub` 子块追加前瞻信息**(2026-09-07 启源Q06 教训):L3/L4 级自动驾驶研发进度、Robotaxi 牌照等前瞻信息,用户要求加到本期重点横幅卡里、与上方智驾看点隔开。**做法:横幅 `.desc` 之后加 `.hl-sub` 子块,用 `border-top:1px solid rgba(255,255,255,.08)` 虚线分隔,字号略小(15px)、灰色 `--text-dim`。关键词(L3/L4/Robotaxi)用金色 `<em>` 高亮。**
31. **品宣自检:功能网格完成后反向 grep 一遍品宣话术**(2026-09-07 启源Q06 教训):"400+ 场景智能泊车辅助"是官方品宣描述,不是配置表逐项,被自检发现后从功能网格移除。**规则:功能网格写完后,把已放入卖点卡的品宣关键词(如"400+ 场景""全场景绕障""交互式领航")grep 一遍页面,确认它们没有同时出现在功能网格的 `.fg-name` 或 `.desc` 里。品宣话术只在卖点卡出现一次,功能网格只列配置表逐项。**

## 一页最多 2 款车 + 拆页做法(重要)

**一页最多 2 款车。** 2026-08-24 成都车展 5 车做成一页,用户嫌「页面太大」→ 拆成 2+3;3 车那页仍嫌长 → 再拆成 1+2(一天连拆两轮)。**做页面时直接按 1~2 车一页规划,别等用户提。** 分组按用户指定的分组走(不一定是原页顺序)。

**拆页做法**:CSS/HEAD、导出脚本整块照抄(逐字节复用,别重写),按 HTML 注释锚点切原页(`<!-- ===== Hero ===== -->`、`<!-- ===== digest-panel ===== -->`、`<!-- ====== NN 车型 ====== -->`、`<!-- ===== footer ===== -->`),重组成 HEAD + 新 Hero + 新横幅 + 选中的车型分区 + footer。每页各自改 6 处:

1. `<title>` —— 只列本页车型。
2. **Hero**:`.brand` 只列本页品牌、`h1` 只列本页车型名、`.lead` 只讲本页车的事件。
3. **本期重点横幅**:标题按本页车数重写,desc 只留本页车。
4. **`.idx` 序号从 01 重排**(按用户给的顺序)。
5. **footer 免责只提本页车**(顺手再精简一次)。
6. **导出 PNG 文件名**——在导出脚本里出现**两处**(`a.download` 和预览遮罩层的下载链接),两处都要改。

**拆完做内容守恒校验**:两页的卡片数相加 = 原页(`grep -c` 数 `section` / `feature-headline` / `hw-item` / `safety-item` / `func-group` / `scap` / `ota-tag` / `sys-note`),再交叉 grep 确认没有串车(A 页里 B 车关键词计数 = 0)。

**拆完记得问用户旧页要不要删**(被拆掉的原页会留在目录里成为僵尸文件)。

## 三处日期口径(重要,勿混淆)

- **页面顶部「YYYY年M月D日 · 内部速递」= 资讯推送日 = 做页面的当天**。
- **页面正文的日期 = 事件本身时间**:新车上市/预售日、OTA 版本推送日,是车企官方时间点,**通常早于**推送日。
- **文件名 `YYYYMMDD` + 导出 PNG 名 = 做页面的当天(= 顶部内部速递日)**,标记"这份资讯何时产出",不是事件日。
- **千里速闻看板 `date` 字段 = 各车实际上市/版本日(车企事件日)**,看板是车型档案;表头标签写「上市/版本日期」(勿写"推送日期")。

## 卡片排序规则(通用,重要)

- **升级/新增卡按 badge 排序:「新增 +」卡一律放前面,「升级 ↑」卡放后面。** 形态 B 每个主题分区内部都按此排。
- 分区内若用户另指定某张卡位置(如「把 X 卡放到 Y 卡后面」),以用户指定为准。
- 形态 A 功能网格里按颜色分组时:**金色 `.critical` 卡一起放前面、普通(主色)卡一起放后面**。若用户说「把某几项直接放到 X 后面」而其中含金色项,按金色归组处理并**主动说明一句**,让用户可以改成字面顺序追加。

## 主功能 + 细分功能的层级卡(形态 A 功能区,重要)

⚠️ **前提:细分能力也必须真在官方配置表里逐项列出。** 不要把品宣话术当细分 chip(见核心原则 2)。确认之后再按层级组织:

配置截图里 `-` 前缀项就是上一条主功能的子项。**细分功能必须和它的主功能对齐放一起,不能笼统地把所有子项拆成一两个大块另放**(曾把 NOA 细分/泊车细分各堆成通用大块,被纠正)。做法用 `.func-group` 卡:

- ⚠️ **删到只剩一个子项时,不要留一个孤零零的 chip 挂在虚线下面**——把卡名写成「主功能 · 子项」一行,`.fg-sub` 整块删掉。例:红旗HS5「巡航系统」下删掉定速巡航/SACC 后只剩高速领航辅助 → 卡名直接写 `巡航系统 · 高速领航辅助`。**这条可以主动提议**(2026-08-24 我提了,用户回「对,写成一行…不带下挂 chip」)。
- **若官方配置是平铺不分主子的**,别硬造层级——直接一排排 `.func-group` 平铺,统一两个一行。
- 领航/关键安全类主功能卡加 `.critical`(金色边)高亮。**两张金色卡也可以并排一行**(用户点名要求把「巡航系统 · 高速领航辅助」和「匝道自动驶出(入)辅助」放一行)。

### 嵌入原图配图(形态 B 常见需求)

- 用户提供的原始卡片图常是竖长图、一张拼多张卡、620px 宽。**先逐张 Read 辨认**每张长图含哪几张卡、各对应哪条功能,建立 文件+区段→功能 映射,不要靠猜。
- **切分多卡竖长图**:每张卡上半是标题文字(白底、只在左侧)、下半是实拍/车机截图(跨全宽)。**按「右半侧(约 45%~100% 宽)逐行平均亮度 < 232」检测截图带**比全行亮度准(纯 dark-band 法会漏检浅色截图)。连续 >150px 的带即为一张截图。
- **⚠️ 白边坑**:切出的截图两侧常各留 ~44px 页面背景白边。裁完后**再按列平均亮度 >230 从左右两侧 trim**(同理 trim 顶/底近白行)。
- **去小红书水印**:把照片带**底部约 10%~11% 裁掉**。
- **每条 feature 最多配一张图**;**Hero 和 footer 不配图**。删卡时对应图也不要留(md5 比对确认)。
- `<img class="shot">`:`width:100%;margin-top:18px;border-radius:12px;display:block;`;边框用 `1px solid rgba(0,0,0,.35)` + `box-shadow:0 6px 18px rgba(0,0,0,.35)`。每张加 `onerror` 兜底虚线占位。

### 图片存放:内嵌 base64 vs 外部 imgs/(与导出直接相关)

- **需要「导出长图」的页面,图片优先内嵌 base64**。外部 `imgs/` 图在本地 `file://` 打开时会导致导出报 `生成失败:undefined`。若干张车机截图 base64 后约 1MB,仍在飞书安全区内。
- 做法:先按 `imgs/xx.png` 搭页面(便于核对),定稿后脚本替换成 `data:image/png;base64,<b64>`。
- **副作用:内嵌后 HTML 极大,`Read` 整文件会超限。** 之后一切改动走 bash:替换用 `python`/`sed`;看片段 `sed -n 'a,bp' 文件 | cut -c1-120`;定位 `grep -n`;重排卡片用 python 切片重组后校验 div 配平;提取正文核对时用正则把 `<img …base64…>` 换成 `[IMG → alt]`。
- 若不需要导出,可保留外部 `imgs/`,但要提醒「HTML 和 imgs/ 要一起打包」。多页面共用 imgs/ 时文件名加车型前缀。

## 导出移动端长图(默认内置)

发布流程:HTML 定稿 → 点页面内「导出长图」→ 上传**飞书机器人消息卡片**。**默认都要内置这个按钮,不用再问。**

### ⚠️ 关键坑:图不是越大越清晰——飞书会把过大的图压糊

**飞书对图片有尺寸阈值:过大会被服务端等比缩小 + 重新压缩 → 手机上看更糊。** 曾把宽度 1080→1600、倍数 2×→3×,结果**反而更糊**;~1080 宽 / 总像素约 1000 万的页面一直清晰。**结论:导出尺寸控制在安全区,不要往上调大**(见记忆 `project_feishu_image_export`)。发布后仍糊 ≠ 质量不够,先把总像素降下来(如 `PIXEL_BUDGET` 调到 800 万),不要往上调。

### ⚠️ 关键坑:导出报「生成失败:undefined」= 外部图被 file:// 挡住

页面用外部 `imgs/xx.png` 且本地双击 `file://` 打开时,html-to-image 抓外部图被安全策略拦截。**修法:图片内嵌 base64**,并在导出前 `Promise.all` 遍历 `img.decode()` 等图解码完再测高/渲染。

### ⚠️ 导出两侧留白过宽的收窄

`EXPORT_WIDTH=1080` 而 `.wrap` 只 820px,两侧各留约 130px。**修法:离屏克隆后、渲染前把克隆里 `.wrap` maxWidth 撑到 `EXPORT_WIDTH-130`(约 950px)。** 不改 EXPORT_WIDTH,也不影响浏览器阅读宽度。
```js
const cw = clone.querySelector('.wrap');
if(cw) cw.style.maxWidth = (EXPORT_WIDTH - 130) + 'px';
```

### 做法要点(踩过的坑,务必照做)

1. **固定导出宽度 1080**:离屏克隆 `.container/.wrap` 重新渲染,不受屏幕 DPR 影响。
2. **像素预算反推清晰度**:`ratio = Math.min(MAX_SCALE, Math.sqrt(PIXEL_BUDGET/(EXPORT_WIDTH*H)))`,`pixelRatio: ratio` 保证 宽×高 ≤ `PIXEL_BUDGET`(默认 **1000万**),预算内最高 `MAX_SCALE=2`。
3. **必须用 `html-to-image`,不要用 `html2canvas`**:html2canvas 不支持 `background-clip:text` 渐变字(标题/大数字会变色块)。用 cdnjs 的 `html-to-image/1.11.11`(原生 SVG `foreignObject`),`toPng` 清晰无损。
4. **首帧空白修复**:`await document.fonts.ready` + 等所有 img decode + `setTimeout 120ms`,再做一次「热身渲染」(toPng 一次丢弃),然后正式 toPng;加 20s 超时保护(`Promise.race`)。
5. **自动下载会被拦 → 加预览层兜底**:生成后 `<a download>.click()`,同时弹预览遮罩显示图 + 「下载图片」按钮 + 尺寸/像素/MB 信息。⚠️ **PNG 文件名在这段脚本里出现两处**(`a.download` 和遮罩里的下载链接),改文件名/拆页时两处都要改。
6. **加载失败要明确报错**:CDN 脚本 `onerror` 置标志位,库未加载时弹窗提示「用真正浏览器双击打开 + 需联网加载一次 CDN」。
7. 按钮 `position:fixed` 右下角、`@media print{display:none}`;离屏容器用 `z-index:-1`(不要 `left:-99999px`,否则某些浏览器测高为 0);`backgroundColor` 用页面 `--bg` 实值。

顶部留 3 个可调参数带注释:`EXPORT_WIDTH`(1080)/ `PIXEL_BUDGET`(1000万,飞书安全区,**勿调大**)/ `MAX_SCALE`(2)。完整实现见范例页末尾脚本块,可整段复制。

> 注:按钮依赖联网加载一次 CDN。若访问不了 CDN,改走服务端渲染兜底(让用户交定稿 HTML,直接输出符合像素上限的长图)。注意 VM 里 pip/npm/apt 可能被代理挡住,先确认工具可用性。

### ⚠️ python 批量改 HTML 的纪律

- **每处替换前先 `assert s.count(old)==1`**,模式写错就中止、不落盘(这条救过一次:一个 `.*?` 正则本会删掉一大块内容,`assert` 先炸了)。
- **⚠️ 别用 `(<svg.*?</svg>)` + `re.S` 这类跨行懒惰匹配去定位卡片**——它会从上一处 `safety-item` 一路吞到很远,`m.group(0)` 里塞进整段别的卡。**改用按行定位**:`idx=[i for i,l in enumerate(lines) if '关键词' in l]`,确认只有一条命中后 `lines.pop(idx[0])`,再从这一行里抽 SVG、拼新结构。
- 切块时**先打印 `blk[0]` / `blk[-1]` 确认边界**(曾把 7 行的块切成 6 行,`assert blk[-1]=='</div>'` 失败)。
